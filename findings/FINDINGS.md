# Empirical findings (report-aligned)

This folder holds **frozen snapshots** of outputs from the same pipelines described in the final report (Section 4). They were generated by the scripts under `experiments/` with the seeds and defaults baked into those scripts. Re-running the scripts may yield slightly different numbers if you change seeds or hyperparameters; the **structure** of the conclusions should remain the same.

## How to regenerate

From the repository root, with dependencies installed (`pip install -r reward_atlas_transfer/requirements.txt`):

```bash
python experiments/q1_binary_dag_linear_loglinear/run.py
python experiments/q2_binary_dag_cumulant_order/run.py
python experiments/q3_binary_dag_warm_start/run.py
python experiments/gym_tabular_benchmarks/run.py
```

Then copy fresh JSON into this folder if you want to update the snapshot:

```bash
cp outputs/binary_dag/*.json findings/binary_dag/
cp outputs/gym_tabular_benchmarks/*.json findings/gym_tabular/
```

## 1. Binary DAG (Sections 4.1–4.4)

**Artifacts:** `findings/binary_dag/q1_binary_dag.json`, `q2_binary_dag.json`, `q3_binary_dag.json`

### Q1 — Linear vs log-linear (Section 4.2)

- **Linear rewards:** Under a fixed descendant measure, the decomposition \(h_w(s) = \Psi(s)^\top w\) holds to **machine precision** (max absolute error on the order of \(10^{-15}\) over random \(w\)). This matches Proposition 1 in the report.
- **Log-linear rewards:** A **single** global linear model \(\log h_w \approx B^\top w\) fit across many \(w\) leaves **non-zero** log-space RMSE on internal states and non-zero terminal KL when that misspecified \(\log h\) is turned into a forward policy. This is consistent with Proposition 2 (no global \(w\)-independent linearization of \(\log h_w\) unless features degenerate).

### Q2 — Cumulant order (Section 4.3)

- We sweep \(\|\Delta w\|\) along one random direction from a reference \(w_0\).
- **Second-order** approximation (mean under tilted measure plus \(\frac{1}{2}\Delta w^\top \Sigma \Delta w\)) achieves **much lower** terminal KL than **first-order** at moderate \(\|\Delta w\|\) (e.g. in this snapshot, improvement ratio first/second on the order of \(10^1\)–\(10^2\) near \(\|\Delta w\| \approx 0.1\)–\(0.4\)).
- At **large** \(\|\Delta w\|\), the ratio moves toward 1 or below 1: the quadratic term can **overshoot**, matching the report’s discussion of higher-order / boundary effects.

### Q3 — Warm starts at zero steps (Section 4.4, Table 1 style)

- **Scratch** (uniform policy): terminal KL to the target-optimal distribution is large (order \(10^0\) in this snapshot).
- **Fine-tune** (start from reference policy at \(w_0\)): better than scratch but still substantial when \(\|w' - w_0\|\) is moderate.
- **First-order** and **second-order** analytical warm starts: terminal KL at **zero optimization steps** drops by many orders of magnitude versus scratch/fine-tune, with second-order typically best. This matches the qualitative Table 1 pattern in the report (exact numerical match to the PDF is not expected without identical seeds and task definitions).

## 2. Gymnasium tabular benchmarks (Section 4.5)

**Artifacts:** `findings/gym_tabular/direct_*.json` (one file per config variant) and `findings/gym_tabular/all_results.json` (full bundle).

**Environments included:** FrozenLake 4×4 and 8×8 (deterministic and slippery), CliffWalking (deterministic), Taxi with horizons \(H \in \{20, 40, 80\}\).

**Per-task metrics (see JSON):**

| Field | Meaning |
|-------|---------|
| `terminal_kl_naive` | KL between terminal distribution under **exact** target tilt vs **naive** reuse of anchor policy |
| `terminal_kl_single_o1` | KL vs **first-order** geometry transfer |
| `terminal_kl_single_o2` | KL vs **second-order** geometry transfer |
| `realizability_gap_mean` | Mean action-space realizability gap \(\Gamma\) (relevant for **stochastic** dynamics; near zero for deterministic envs in exact tabular solves) |

**Qualitative patterns visible in the snapshot:**

- On **deterministic** FrozenLake variants, second-order transfer often improves sharply over first-order on shifted tasks (see `hole_penalty`, `fast_goal`, etc. in the JSON).
- On **slippery** FrozenLake, **naive** terminal KL can sit well above geometry-based transfer; `realizability_gap_mean` is **non-zero**, reflecting the stochastic realizability gap discussed in the report.
- **Taxi** results depend strongly on horizon \(H\); small \(H\) can be a poor match to long effective trajectories (finite-horizon augmentation is explicit in the codepath).

For paper-style **selected rows** (single task / single shift), extract the relevant `task` entry from the appropriate `direct_*.json` file rather than comparing across different YAML task names.
